# VS Code Copilot Chat 貼り付け用プロンプト集

このファイルには、VS Code の Copilot Chat（`@workspace`）で使用する以下の3種類のプロンプトを収録しています。
1. **初回引き継ぎプロンプト（開発スタート用）**: スクリプト一式を新規作成するときに1回だけ使用します。
2. **日常運用プロンプト集（ステップ1〜4）**: スクリプト完成後、毎回の山行記録追加時に上から順に使用します。
3. **メンテナンス用プロンプト**: 既存の正本Excel（`records_master.xlsx`）の `map` 列を一括修正するときに使用します。

---

## 1. 初回引き継ぎプロンプト（開発スタート用）
※リポジトリに `yamareco_workflow_spec.md` を保存したあと、以下をコピーして Copilot Chat に送信してください。

```markdown
@workspace #file:yamareco_workflow_spec.md

上記の仕様書（yamareco_workflow_spec.md）に基づき、新規山行記録の生成・追加ワークフローを自動化するPythonスクリプト群と検証コードをリポジトリ内に実装したいです。

【前提・運用方針・作業スタイル】
1. 外部のLLM API（OpenAI等）は使わず、工程2の `sm2`（180〜230文字の要約）の生成は VS Code の Copilot Chat 上で行う半自動ハイブリッド構成（2-A: Python前処理 → 2-B: Copilotによる要約生成 → 2-C: Python取り込み＆文字数検証）にします。
2. 普段の運用では、私が工程1で保存した作業用Excelファイル（`recordsyyyymmdd.xlsx`）を `@workspace` に添付（指定）して対話しながら進めます。一発でブラックボックス的に全部書き換えるのではなく、各工程の間に確認（チェックポイント）を挟み、その確認作業自体もできる限り検証スクリプトで自動化したいです。
3. 作業用ファイル（`recordsyyyymmdd.xlsx`）は Microsoft Excel だけでなく、Google スプレッドシートから `.xlsx` 形式でダウンロードしたものを使う場合もあります。日付形式の揺れ（`yyyy/m/d` やシリアル値など）や空セル（`NaN`）も正しく吸収して処理できるよう実装してください。
4. 工程4の地図URL整形スクリプトは、作業用ファイルだけでなく既存の正本ファイル（`records_master.xlsx`）に対しても実行できるよう、対象ファイルを引数で指定でき、すでにURLのみになっている行は変更しない（冪等性のある）仕様にしてください。
5. このドキュメントおよびスクリプトは今後の保守や機能追加にも使うため、コード内のコメントや出力メッセージも分かりやすく整理してください。
6. 工程6・7については、このリポジトリ内にある既存の `excel_to_json.py`、本番JSONファイル、および既存のJekyll用Markdown記事の形式・命名規則を調査した上で、それらと完全に整合する形で実装してください。

まずはリポジトリ内の既存ファイル（`excel_to_json.py`、JSON、Markdown記事）の構造を確認し、作成すべきスクリプトのフォルダ構成と設計案を提示してください。
```

## 2. 日常運用プロンプト集（毎回の山行記録追加用）
※使用時は `#file:recordsyyyymmdd.xlsx` の日付部分を、その日の作業用ファイル名（例：`#file:records20261124.xlsx`）に書き換えて貼り付けてください。

### ステップ1：前処理 ＋ AI要約（`sm2`）生成 ＋ 自動検証【工程2】
**タイミング**: ヤマレコCSVを `recordsyyyymmdd.xlsx` として作業フォルダに保存した直後

```markdown
@workspace #file:yamareco_workflow_spec.md #file:recordsyyyymmdd.xlsx

仕様書（yamareco_workflow_spec.md）の「工程2」を実行してください。

1. 前処理スクリプトを実行し、23項目への整形・日付/日数/ID算出・summaryの署名削除を行う。
2. 整形された各レコードの `summary` をもとに、仕様書の「sm2（一覧表示用要約）生成ルール（180〜230文字・時系列・箇条書き禁止）」に従って `sm2` を生成する。
3. 取り込み＆検証スクリプトを実行し、文字数・日付形式・欠損値のチェック結果を報告してください。
```

### ステップ2：手動作業（写真・コメント・地図コード登録）【工程3】
*(※ここは手作業です)*
1. Excel または Google スプレッドシートで `recordsyyyymmdd.xlsx` を開く。
2. ヤマレコの記録ページから以下を貼り付ける。
   * 代表写真リンク → `tm` ／ コメント → `tmfg`
   * ギャラリー写真リンク → `gp1`〜`gp3` ／ コメント → `gpfg1`〜`gpfg3`
   * ブログ貼り付け用地図コード → `map`
3. 上書き保存（スプレッドシートの場合は `.xlsx` でダウンロードして作業フォルダに上書き）する。

### ステップ3：地図URL整形 ＋ 正本Excel統合 ＋ JSON差分作成【工程4〜6】
**タイミング**: 写真・地図URLの貼り付けと保存が終わったあと

```markdown
@workspace #file:yamareco_workflow_spec.md #file:recordsyyyymmdd.xlsx

工程3（写真・コメント・地図URLの登録）が完了しました。
仕様書の「工程4〜工程6」を順に実行してください。

1. 【工程4】`map` 列の `<iframe>` コードを除去し、URL形式の自動検証を行う。
2. 【工程5】`records_master.xlsx` との `record_id` 重複チェックを行い、問題なければ降順で正本の先頭へ統合する。
3. 【工程6】`excel_to_json.py` 等を実行して追加分のJSONを生成し、本番JSONへ反映する前の「差分（diff）」を表示して停止してください。
```

### ステップ4：本番JSON反映 ＋ Markdown記事生成 ＋ 整合性チェック【工程6完了〜工程7】
**タイミング**: ステップ3で表示された JSON の差分を確認し、問題ないと判断したあと

```markdown
@workspace #file:yamareco_workflow_spec.md

先ほど確認したJSONの差分で問題ありません。本番JSONへの反映と「工程7」を実行してください。

1. 本番JSONファイルを更新する。
2. 本番JSONをもとに、Jekyll公開用のMarkdown記事ファイルを生成する。
3. JSON内の `record_id` と生成されたMarkdownファイルの対応関係・フロントマター形式に過不足がないか検証スクリプトで確認し、結果を報告してください。
```

## 3. メンテナンス用プロンプト（既存正本の `map` 一括修正）
※実行前に必ず `records_master.xlsx` のバックアップ（`records_master_backup_yyyymmdd.xlsx`）を作成してから貼り付けてください。

```markdown
@workspace #file:records_master.xlsx #file:yamareco_workflow_spec.md

既存の正本ファイル（records_master.xlsx）の全レコードについて、工程4の「地図インラインフレーム用コードの除去スクリプト」を実行してください。

【実行条件】
1. すでにURLのみ（https://...）になっている行はそのまま変更しないこと。
2. <iframe> タグが含まれている行のみ、純粋な地図URLを抽出して上書きすること。
3. 処理完了後、変換された件数・変更なしの件数・エラー（URL形式になっていない行）の有無を検証スクリプトで確認して報告してください。
```
